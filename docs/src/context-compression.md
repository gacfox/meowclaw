# 上下文压缩

MeowClaw 为长流程对话设计了多级上下文压缩机制，在尽量不丢失上下文记忆的前提下持续交互。这里的 1 个 batch 指 1 次完整的 ReAct Agent 交互，其中可能包含多次工具调用迭代。

## 水位线预警

1 个 batch 执行完成后，系统会根据上下文占最大上下文长度的比例进行预警：

- 达到 **82%** 时，前端显示“上下文不足”；
- 达到 **93%** 时，前端显示“上下文严重不足”。

## 会话滚动摘要

1 个 batch 执行完成后，系统会自动对 **5 个 batch 之前**的内容使用大语言模型生成滚动摘要（Rolling Recap），并注入系统提示词。

每个 batch 生成一个滚动摘要。当滚动摘要达到 **20 个**时，系统会自动将前 **1～6 个**压缩合并为 1 个合并滚动摘要（Rolled Up Recap），使滚动摘要总数保持不超过 20 个。

## 工具消息折叠

工具调用及其返回可能占用大量上下文，因此 MeowClaw 会自动折叠较早内容中的工具调用信息。折叠分为两个层级：

### Level 1：截断较长的工具返回值

对于 **5 个 batch 之前**的工具调用消息，如果返回值中的内容字符数大于 **100**，则直接截断为：

```text
xxxxx... [此处因上下文压缩已截断]
```

### Level 2：移除工具调用相关消息

对于 **15 个 batch 之前**的交互，直接移除工具调用相关消息，只保留用户输入和助手普通正文。

## 主动消息压缩

在上述压缩机制的基础上，如果一次交互前的上下文占用仍大于 **93%**，系统会立即先触发主动消息压缩，再执行任务。

这一过程根据 tokens 消耗计算，将 **n（n ≥ 0）个 batch 之前**的消息暴力压缩为 1 个主动压缩滚动摘要（Proactive Recap），以腾出上下文空间，继续执行任务。

## 压缩层级概览

| 机制 | 触发条件或范围 | 处理方式 |
| --- | --- | --- |
| 水位线预警 | batch 完成后达到 82% / 93% | 分别提示上下文不足 / 上下文严重不足 |
| 会话滚动摘要 | batch 完成后，处理 5 个 batch 之前的内容 | 每个 batch 生成 Rolling Recap 并注入系统提示词 |
| 摘要合并 | 滚动摘要达到 20 个 | 将前 1～6 个合并为 1 个 Rolled Up Recap，总数不超过 20 个 |
| Level 1 折叠 | 5 个 batch 之前的工具调用消息 | 返回值内容超过 100 个字符时截断 |
| Level 2 折叠 | 15 个 batch 之前的交互 | 移除工具调用相关消息，仅保留用户输入和助手普通正文 |
| 主动消息压缩 | 交互前上下文占用仍大于 93% | 先按 tokens 消耗计算范围，将 n（n ≥ 0）个 batch 之前的消息压缩为 Proactive Recap，再执行任务 |
